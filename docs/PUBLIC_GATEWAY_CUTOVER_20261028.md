# Cartoon Universe 3.0 — separate production web gateway cutover (review only)

**Not launched.** The existing public Render static site must continue publishing `deploy/public-maintenance` until the gateway is independently tested and the owner explicitly authorizes the cutover. Never publish `preview-public`, run the review-only static builder, or turn `server/gateway-candidate.mjs` into production by changing a flag.

## Architecture

- The existing **free web service** `srv-dbf20i7avr4c73chisug` is the only dynamic request gate. After a **branch and start-command change**, it runs the *new* `server/public-launch-gateway.mjs` (not the candidate). It serves a fixed, reviewed asset allowlist directly from the checked-in repository; no review bundle is deployed.
- Anonymous users can see public arcade routes **only** when the live `site_maintenance` read says `enabled=false`. Any Supabase failure, missing row, malformed response, or enabled maintenance state fails closed with HTTP 503. Health returns only process liveness, not release readiness.
- Owner sign-in and recovery live at `/__maintenance/owner-signin` and `/__maintenance/password-recovery`, independent of maintenance. A short-lived secure HttpOnly cookie is issued only after Supabase Auth verifies the access token and owner membership under RLS. `/__maintenance/arcade/*`, `/owner.html`, and owner-only scripts are server protected. Nonowner tokens cannot unlock them. Coin wallet and maintenance mutations remain subject to production Supabase RLS/RPC policies.
- The existing **static site** `srv-dbeg2nu7bikc738b8ulg` remains a maintenance-only holding page until verified. Because static hosting cannot perform request-time authentication, it must **never** serve the full combined site. After the gateway is ready, the static site can redirect to the gateway domain using Render Dashboard redirects and a deliberately asset-free publish directory. This changes the browser origin to the gateway URL; no transparent reverse proxy is assumed.

## Rollback

Keep `deploy/public-maintenance` in the repository. Restore the public static site's **Publish Directory** to `deploy/public-maintenance`, remove the two external redirect rules, and redeploy the static service. Re-enable maintenance using the authorized owner dashboard if needed. Do not revert Supabase RLS or change Cartoon Coin balances. Keep gateway auto deploy off.

## Known gates

- Existing Supabase Auth recovery redirect has not been confirmed.
- Real owner/player authentication, logout, recovery and browser verification are not replaced by mocked CI.
- The two pre-existing Supabase advisories (authenticated SECURITY DEFINER daily reward RPC and leaked-password protection unavailable on the free plan) require documented risk review; no production SQL/Auth setting changes are authorized by this review.
- A public static Render URL cannot act as a transparent secure gateway. A redirect changes the browser URL to the web-service origin; retaining the static `onrender.com` URL as the actual authenticated origin would require a different hosting/domain architecture.
